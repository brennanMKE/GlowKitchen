# 0007 — Retire the Halloween and Christmas themes; seasonal colors become scheduled custom effects

| | |
|---|---|
| **Status** | open |
| **Module** | Themes / Documentation |
| **Platform** | ESP32-C3 |
| **First seen** | 2026-08-15 |

## Description

Halloween and Christmas are gone from the firmware already — they were removed in `bf336b2` (2026-02-02) along with the other seasonal themes. What remains is stale documentation that still advertises both as working commands. This issue closes that gap and records the decision behind it: seasonal palettes are not built-in themes, they are custom effects sent over MQTT and scheduled externally.

## Long Description

### What is actually left

`src/main.cpp` has no trace of either: no `HueTheme` enum entries, no hue arrays, no `THEME_NAMES` strings, no MQTT aliases. `scripts/set_theme.sh` validates against `GREEN RAINBOW PINK_PONY OCEAN_WAVES SUNSET FOREST`, and `glowpanel` lists the same six. The firmware will simply ignore a `HALLOWEEN` or `CHRISTMAS` payload — it falls through the theme matching in `onMqttMessage()` and nothing happens.

The only references are three lines in `docs/mqtt_commands.md`:

- line 39 — `| \`HALLOWEEN\` | Switches immediately to the Halloween theme (orange/purple). |`
- line 40 — `| \`CHRISTMAS\` | Switches immediately to the Christmas theme (red/green). |`
- line 111 — `**THEME**: \`GREEN\`, \`RAINBOW\`, \`PINK_PONY\`, \`HALLOWEEN\`, or \`CHRISTMAS\`.`

Anyone following that doc sends a command that silently does nothing, which is worse than a missing doc.

### Why they are not coming back as themes

A built-in theme costs an enum entry, a hue array, a name string, three `switch` arms, and firmware flash — permanently — to serve two days a year. It also cannot be scheduled without more firmware, and adding a seventh holiday means another release.

The custom-effects work in `docs/glowkitchen-custom-effects-spec.md` makes all of that unnecessary. Its `SET_EFFECT` command already carries arbitrary colors, an effect mode, speed, intensity, and an auto-revert timeout:

```
SET_EFFECT:{"mode":"CHASE","colors":["#FF6600","#7B2FBE"],"speed":128,"intensity":180,"timeout":86400}
```

That is Halloween, with no firmware change. Christmas is the same call with `["#CC0000","#0B6623"]`. Any other holiday is a new line in a script, not a new release.

### Scheduling comes free from the existing cron pattern

The Pi already publishes scheduled MQTT commands — `rainbowpi/glowkitchen/glow-evening.sh`, `glow-normal.sh`, `glow-dim.sh`, `glow-off.sh` run at 17:00 / 18:00 / 23:00 / 02:00. A seasonal palette is the same mechanism with a date-based cron entry rather than a time-based one, publishing `SET_EFFECT` instead of a brightness. No device-side calendar, no NTP-dependent holiday logic in firmware, and holidays can be changed without touching a device.

The `timeout` field means a holiday effect can even self-expire back to the normal theme without a second scheduled job.

### Scope of this issue

1. Remove the three stale lines from `docs/mqtt_commands.md`.
2. Note in that doc that seasonal/one-off colors are done with `SET_EFFECT` once [#0008 / the effects work](0004.md) lands, so the removal reads as a redirect rather than a deletion.
3. Once custom effects exist, add a `glow-holiday.sh` helper alongside the other Pi scripts, plus example cron entries for Halloween and Christmas.

Steps 1–2 can be done now; step 3 depends on the effects engine.

### Adjacent staleness in the same file

Worth fixing in the same pass, since it is the same document and the same class of error:

- The **MQTT Topics** table lists only `all`, `kitchen`, `tv`, `desk`. It is missing `workbench` and `recycling`, both of which are live.
- The **Configure Device Hardware** section documents `./scripts/configure_device.sh [location] [numLeds] [optional: ledsPerColor]`. The script's actual interface is `[device] [option] [value]` with options `num_leds`, `leds_per_color`, `brightness`, `name`, `ir`, `mirror`, and now `ota_auto`.
- `SET_MIRROR`, `MIRROR_ON` / `MIRROR_OFF` / `TOGGLE_MIRROR`, `SET_DEVICE_NAME`, `SET_IR_FLAG`, and `STATUS` are all implemented but undocumented.

## Expected behavior

The MQTT documentation lists only commands the firmware actually implements, and points at `SET_EFFECT` for seasonal colors.

## Actual behavior

`docs/mqtt_commands.md` advertises `HALLOWEEN` and `CHRISTMAS`, which the firmware silently ignores, and omits several commands it does support.

## Notes

- No firmware change is required for this issue. The retirement already happened; this is documentation catching up to it.
- Deliberately not adding the themes back as a stopgap for this year's holidays — the effects engine is the intended path, and a temporary theme would have to be removed again.
