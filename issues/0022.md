# 0022 — Theme and effect switches snap instantly instead of crossfading over one second

| | |
|---|---|
| **Status** | open |
| **Module** | Firmware / LED |
| **Platform** | ESP32-C3 |
| **First seen** | 2026-09-09 |

## Description

Switching themes or effects changes the strip on the very next frame — a hard cut. It should crossfade: the outgoing look fades out while the incoming one fades in, over a **full second**, then the old one is torn down.

## Long Description

Today `loopLED()` renders one `EffectState` into the single `leds[]` buffer and pushes it with `FastLED.show()`. A theme change swaps the palette pointer; an effect change swaps `EffectMode` and calls `resetEffectState()`. Either way the next frame is already fully the new look.

A crossfade means running **two renderers in parallel** for the transition window: the old mode/palette and the new one each render into their own buffer, and the two are mixed per-LED by a progress factor before `show()`. `EffectState` was deliberately written to make that possible — its header comment says a test can "construct two independent instances and diff their output", and every renderer writes only through `s.leds` / `s.numLeds`. The open questions are memory (a second `CRGB[MAX_LEDS]` at MAX_LEDS = 500 is 1500 bytes of RAM), which state must be duplicated (`timeouts[]` and `sparkleVal[]` are per-LED side buffers, so a second renderer needs its own or must be made not to need them), what happens when a second switch arrives mid-fade, and whether brightness/power changes should ride the same mechanism.

## Expected behavior

- Any change of theme, effect, or custom-effect config starts a 1000 ms crossfade from the currently-rendered look to the new one.
- The transition is smooth on the strip — no visible stutter, no frame-rate drop, no flash to black or white between the two looks.
- Both looks stay *animated* during the fade (this is a crossfade of two live animations, not a fade through a frozen snapshot) unless the plan finds a good reason otherwise.
- After 1000 ms the new look is rendered alone and the transition state is released.
- A second switch arriving mid-fade is handled sanely and never leaves the strip stuck part-way blended.

## Actual behavior

The new theme or effect appears in full on the first frame after the command lands. There is no transition at all.
