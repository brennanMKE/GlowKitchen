|---|---|

## Description

A set of real defects found while diagnosing [#0003](0003.md) that were deliberately **not** shipped in `v0.0.4`, so that release stays a clean diagnostic baseline with no change to the LED render path. Each is independently fixable and none is believed to be the cause of the static-red fault. They should land once [#0003](0003.md) is understood.

## Long Description

### 1. `slowBlend()` never spans a full palette on short strips

**This one is written and was backed out of `v0.0.4`.** The gradient repeats every `ledsPerColor × hueCount` LEDs. When that period exceeds `numLeds`, only a slice of the palette is on screen and `blendOffset` drifts it just one LED per 500 ms, so the strip reads as one slowly-wandering color.

It is **not** the cause of [#0003](0003.md) — kitchen set to 30/color is exactly one full rainbow across its 240 LEDs and still showed solid red — but it is a genuine defect, and much worse for the wide themes than for Rainbow. Sunset has 18 hues and Forest 16, so on `recycling` (58 LEDs, 20/color) Sunset needs 360 LEDs to display once and shows roughly a sixth of its palette.

Current fraction of the palette visible at any instant:

| device | Rainbow (8 hues) | Sunset (18 hues) |
|---|---|---|
| kitchen (240 @ 32) | 94% | 42% |
| tv (60 @ 10) | 75% | 33% |
| desk (50 @ 10) | 63% | 28% |
| recycling (58 @ 20) | 36% | 16% |
| workbench (128 @ 8, mirrored) | 100% | 44% |

The fix clamps the group size so a whole palette always fits, treating `ledsPerColor` as a preferred maximum rather than an absolute. Verified by simulation to leave `workbench` and `Dev` byte-identical on Rainbow — the two strips that render correctly today — while giving every other strip a full palette:

```c
// in slowBlend(), replacing the raw ledsPerColor arithmetic
int visibleSpan = mirrorEnabled ? (numLeds / 2) : numLeds;
if (visibleSpan < 1) visibleSpan = 1;
int perColor = max(1, min(ledsPerColor, visibleSpan / currentHueCount));
int patternPeriod = perColor * currentHueCount;

for (int i = 0; i < numLeds; i++) {
    int effectiveLedPosition = (i + blendOffset) % patternPeriod;
    int groupIndex = effectiveLedPosition / perColor;      // already < hueCount
    int nextGroupIndex = (groupIndex + 1) % currentHueCount;
    ...
    int ledInGroup = effectiveLedPosition % perColor;
    float blendFraction = (float)ledInGroup / (float)perColor;
```

and the rotation becomes `blendOffset = (blendOffset + 1) % patternPeriod;`.

### 2. `blendOffset` is `uint8_t` and cannot hold a full pattern period

`blendOffset` is assigned `(blendOffset + 1) % (numLeds * currentHueCount)`, which for kitchen is mod 1920 — a value the variable cannot represent. It silently wraps at 256, so the rotation covers the intended range only by coincidence when the period happens to divide 256. Widen to `uint16_t`; it pairs with fix 1, which reduces the modulus to the actual pattern period.

### 3. `publishState()` is called from inside the MQTT callback

`onMqttMessage()` calls `publishState()` directly (the `STATUS` branch and every setter). PubSubClient uses **one shared buffer** for send and receive, so publishing from within the callback — while the library still owes a QoS 1 PUBACK for the message being handled — can corrupt that buffer.

This is not theoretical: `glowpanel` publishes `STATUS` at QoS 1, so the whole fleet was doing this every ~8 seconds until it was stopped. Set a `statePublishPending` flag in the callback and publish from `loop()` instead.

### 4. Retained theme commands conflict on connect

`lights/all/cmd` currently retains `FOREST` while each device topic retains its own theme (mostly `RAINBOW`). Devices subscribe to both in `ensureMqtt()`, so **every reconnect delivers two conflicting theme commands**, and which one wins depends on broker delivery order. Each one that changes the theme also writes NVS and repaints the strip.

Both `scripts/set_theme.sh` (publishes with `-r`) and `glowpanel`'s `SetTheme` (`app.go`, publishes retained) create these. Either stop retaining broadcast theme commands, or have the firmware ignore a retained broadcast when a device-specific retained theme also exists. The stale `FOREST` should be cleared regardless:

```bash
mosquitto_pub -h homeassistant.local -u mqtt -P "$MQTT_PASSWORD" -t lights/all/cmd -r -n
```

### 5. `FW_VERSION_MARKER` is still being dropped from the binary

`scripts/firmware_info.sh` reports `0.0.4  (heuristic — no marker; rebuild for reliable detection)`. The `fwVersionMarkerAnchor` workaround in `src/main.cpp` is supposed to pin the marker past `--gc-sections`, and it is not working. Version detection currently succeeds only through the script's fallback heuristic. Either fix the anchor (`KEEP()` in a linker fragment, or `__attribute__((section(...)))` with a retained section) or drop the marker and make the heuristic the documented path.

### 6. Flash headroom is nearly exhausted

`v0.0.4` builds at **99.1%** — 1,298,274 of 1,310,720 bytes, leaving 12,446 free on the default 2×1.25 MB OTA partitions. The custom-effects engine will not fit.

Measured options:

- `CORE_DEBUG_LEVEL` 5 → 3 in `platformio.ini` reclaims **~21 KB** (99.1% → 97.4%) and keeps every project `ESP_LOGI`; only framework debug/verbose logging is lost. Left at 5 for now because it may help diagnose [#0003](0003.md).
- Switching to a `min_spiffs`-style layout would give ~1.9 MB per app slot, but the partition table lives outside the app image, so OTA cannot deliver it — every device would need a USB reflash. Avoid unless genuinely necessary.

## Expected behavior

Every theme displays its full palette on every strip; the MQTT client is not driven into a re-entrant publish; a device receives one unambiguous theme on connect; firmware version is readable from the image directly; and there is enough flash to build the next feature.

## Actual behavior

Wide themes show a fraction of their palette on short strips; `publishState()` re-enters PubSubClient from its own callback; reconnects deliver two competing retained themes; the version marker is absent from the binary; and 12 KB of flash remains.
